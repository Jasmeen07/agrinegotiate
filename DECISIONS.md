# Decisions

Choices made where the build specification was ambiguous or had to be extended.
Each one should be mentioned in the paper's method or limitations section.

| # | Decision | Reason |
| --- | --- | --- |
| 1 | The reference price level varies per episode (uniform 0.70 to 1.10 in grid units) and each farmer's fallback ratio is drawn around theta (plus or minus 0.08). Prices are **not** all normalised so that P_ref = 1. | If P_ref were always 1 on the price grid, the farmer could read the market price off the grid and the information-asymmetry knob would do nothing. With a varying level and a farmer-specific fallback, a noisy signal leaves real uncertainty. Metrics stay normalised by G*, and price share is price / level. |
| 2 | A buyer may only bid a price it could still afford at the last step the bid can be accepted (value decayed to the end of the offer's validity). A buyer may only accept an ask under the same worst case. | An offer stays open for several steps while the crop decays. Without this rule a deal could close after the buyer's value fell below the price, giving negative gains from trade, which spec 11.3 says must be impossible. The rule makes every closed deal individually rational for both sides; the environment asserts it. |
| 3 | WALK closes the thread at once for both sides, even if the farmer's link is down. | A farmer who walks sells to the local trader; the lot is physically gone. Modelling a delayed walk notice adds states without changing any payoff. |
| 4 | A failed ACCEPT clears the sender's "accept pending" flag immediately instead of sending a failure notice through the link. | Simplification of spec 8.3. The sender can see that the thread is still open. Revisit if the delay ablations need it. |
| 5 | While an agent's own ACCEPT is in transit on a thread, its only valid action on that thread is WAIT. | Prevents an agent from accepting and re-offering on the same thread at once. |
| 6 | Deliveries at step t are processed before deadlines at step t. A farmer with deadline D acts at steps 0..D-1 and a deal still counts if it is delivered at step D. | Spec 8.4 did not fix the order of the last two sub-steps for the boundary case. |
| 7 | Drop mode loses a message if the link is OFF at the step it is sent; otherwise it arrives one step later. Store-and-forward delivers at the first step after sending at which the link is ON. | Direct reading of spec 8.2. |
| 8 | In multi-thread markets every thread of an agent is credited with that agent's total terminal reward. | Simplest credit assignment for the thread-level policy of spec 5.7. Noisy for buyers with many threads; revisit in phase 6. |
| 9 | The environment core is a plain per-episode Python class, not a vectorised NumPy batch. | Correctness first. Measured speed is in PROGRESS.md; vectorise before the large sweeps if needed (spec 12.7). |
| 10 | The fastest possible deal closes at step 2 (offer delivered at step 1, accept delivered at step 2). The oracle fair split therefore scores slightly below E = 1, and well below 1 when the crop is perishable. | Consequence of spec 8.2 and 8.3. Report the oracle's E as the protocol ceiling in each scenario. |
| 11 | ZI-C holds each random offer for three steps before replacing it. | A new offer cancels the old one. Re-drawing every step cancelled offers before they could be accepted and made the random baseline artificially bad. |
| 12 | The tuned heuristic tunes only beta (grid 0.2 to 30) per role and scenario, maximising own gain capture against Boulware, Linear, Conceder and tit-for-tat on tuning seeds 0 to 99. | Spec 10.2 also mentions tuning the start price; left out for now. |
| 13 | Learned policies are evaluated by sampling from the policy, not by taking the most likely action. | Bargaining equilibria can be mixed; a deterministic argmax can misrepresent the trained policy. |
| 14 | Rewards are multiplied by 5 inside the learner only. | Gains are about 0.2 in grid units; scaling keeps value targets near unit size. Reported metrics are unaffected. |
| 15 | Farmer share S_F is reported as undefined when E < 0.05 or when either side's total gain is negative. | A share of a total is meaningless when one part is negative. FGC stays the primary fairness number in those cases. |
| 16 | The interquartile mean and its 95% bootstrap interval are computed by our own code (resampling runs with replacement), not by calling rliable. | rliable 1.2.0 could not be imported next to pandas 3 because of its `arch` dependency. For one scenario this is the same statistic. Pin older pandas or switch back if cross-scenario aggregates are needed. |
| 17 | First learned runs use 150 iterations of 256 episodes (about 0.7 million agent-steps), not the 3 million of spec 12.5. | Curves were flat by iteration 120 in SYM. Confirm with a longer run before the paper. |
| 18 | New policies start with the WALK action's logit lowered by 3. | Without it, 3 of 10 PERISH runs collapsed to "everyone walks at step 0": early random play loses money when the crop decays, both sides learn to leave, and trade is never rediscovered. The offset only changes the starting point; agents can still learn to walk. With it, 0 of 10 PERISH runs collapsed. |
| 19 | Bilateral scenario variants were added: RURAL1 and RURAL1-DTN (all RURAL knobs with one farmer and one buyer), THIN3 (three farmers, one buyer), SYMX (SYM with equal uncertainty on both sides). | The 8-farmer markets train several times slower. The mechanism (X3) was run in PERISH and the delay study (X4) in RURAL1-DTN, not in RURAL and RURAL-DTN as spec 12.1 planned. Market-scale runs (X7) remain to be done. |
| 20 | Delay and tau/floor sweeps, and the DEADLINE, INFO and THIN3 gate scenarios, use 3 to 5 seeds. | Compute limits on a two-core sandbox. They are labelled exploratory everywhere; confirmatory claims use the 10-seed runs only. |
| 21 | The front end is one static page (`dashboard/web/index.html`, plain JavaScript and SVG, no build step) served by a FastAPI backend, not a React app, and there is no Streamlit interim version. | Same views and endpoints as spec 16 with nothing to install or build; it also opens directly from disk with recorded episodes. |
| 22 | The dashboard shows prices as a share of the market reference price, not in rupees. | No real price data has been loaded, so rupee values would be invented. |
| 23 | The observable-fee target uses kappa = 0.606, computed by hand from the default parameters as the average oracle target at tau = 0.4 two steps into a PERISH episode. | Spec 7.4 asks for the average oracle target price; a proper calibration from simulated deals is still to do. |
